Phase zero item 2, the photo promise. Three parts of the approved promise were checked against the code. The image request to OpenRouter now carries `provider: { data_collection: 'deny' }`, the preference Store Chat already sends (`lib/try-on/image-runner.ts`). Zero retention could not be confirmed, and the code disagrees with what the note assumed: OpenRouter's public list of zero-data-retention endpoints has none for the try-on model `meta/muse-image`, whose only endpoint is Meta's, and OpenRouter's images endpoint answered a `zdr: true` request for it on 2026-10-16 with a finished image (one cent), while an impossible `provider.only` was refused with a 404 at no cost. So routing filters apply, but `zdr` is not enforced for this model, and sending it would prove nothing; it is not sent. On our side, a finished look now leaves the server once the shopper's browser has it: the embed and the public studio read the look into the page (a signed link is fetched once and kept as a data URL) and then call the new `DELETE /api/try-on/jobs/[jobId]` with the session, which drops the memory copy and deletes the stored object and marks the row deleted (`releaseDurableTryOnResult`). It acts only on a job of the same session, product and shop, and answers 204 either way so it confirms nothing about other jobs. If the browser never confirms, the look lives no longer than a try-on session can read it: `TRYON_RESULT_RETENTION_MS` and the memory TTL went from 30 minutes to the 10-minute session lifetime, and `getJob` now respects the TTL instead of serving expired entries until the next insert. `lib/try-on/phone-store.ts` is the on-phone storage the v16 screens will use: IndexedDB in our iframe's origin, photo and looks for 24 hours from saving and only while "Keep my photo on this phone" is on (turning it off deletes them), consent as a separate record for a year, Delete all, and every call safe when storage is missing or failing. The embed purges expired entries on every load; nothing is saved yet, because the toggle and My looks belong to TryOn-Check and TryOn-States, which ship behind their flags with the try-on surface. `lib/try-on/result-image-boundary.test.ts` keeps the third promise: only the try-on routes, the embed and the studio touch a finished look, and the storefront scripts in the merchant's page never do. The shopper sentence in `lib/try-on/i18n.ts` is unchanged, the README's default until zero retention is confirmed. The public Shopping and Security pages said looks were kept about 30 minutes; they now say until it reaches the browser and 10 minutes at most, in English and Arabic (Arabic drafts). The register entry `privacy.tryon-short-private-flow` and `docs/legal/privacy-policy-draft.md` were updated to match.
