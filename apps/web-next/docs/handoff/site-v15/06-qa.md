06, checks and definition of done

This note says how to prove the work is finished. The rule in `AGENTS.md` applies throughout: failing checks get fixed, never loosened. Where this design changes something a test pins down on purpose, update the test in the same change and say why in the pull request.

Commands. From `apps/web-next`, run `npm ci` once. Then run `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run test:golden` and `npx playwright test mobile-overflow.spec.ts`. `npm run test:golden` leaves out the mobile overflow spec even though CI runs it, so run that one on its own. Run the dev server with `--hostname localhost`, not 127.0.0.1, because Clerk loops otherwise. The Playwright config starts `next dev` on port 3100 and uses the installed Google Chrome, unless you set `PLAYWRIGHT_BASE_URL`.

Unit and guard tests that change. In `app/page.test.tsx`, the heading check moves to the new heading, The fitting room your online store was missing., and its Arabic from `copy/landing.json`. The Book a call link check and the `/try-on` link check stay. `components/landing/site-landing.test.tsx`, `components/landing/site-header.test.tsx`, `lib/landing/landing-i18n.test.ts` and `e2e/fixes-verification.spec.ts` pin parts of the old landing and header, as `02-landing.md` lists. Page tests that render the header, such as `components/roi/roi-page-content.test.tsx` and `components/conversations/conversations-page-content.test.tsx`, may need the new header's links. `app/globals.motion.test.ts` requires reduced motion to keep short opacity and colour transitions, so don't switch those off. Add stubs for IntersectionObserver or matchMedia to `vitest.setup.ts` if the new components need them. `app/golden-landing-standard.test.ts` must pass unchanged, because the landing and pricing pages still import `LandingLocaleProvider` and use the exact root class and the `max-w-7xl` container. If the landing story needs its own motion helpers, add them to the approved list in `docs/golden-landing-standard.md` rather than weakening the guard. The try-on service tests change as `05-backend.md` describes. Add unit tests for the new pieces that carry logic: the story director's stop measuring and gesture-to-beat rules, the try-on page state machine including the failure and abort paths, the tray's four-look limit and restore, the password copy fallback, and the pricing meter and recommended flag.

End to end tests that change. The golden visual spec takes full page screenshots of the landing and pricing pages in English and Arabic at 390, 1024 and 1440, in light theme with reduced motion. With reduced motion, the landing renders its scenes as ordinary stacked sections, so its full page screenshot is meaningful. Regenerate the baselines through the manual `update-visual-baselines` workflow on the pull request branch once the design is final, and attach the new images to the pull request. That workflow commits with the default token, which doesn't start the pull request checks again, so run `next-release-check` by hand afterwards. Local regeneration only produces baselines for your own operating system. In the RTL spec, the check that the first `[data-icon="inline-end"]` icon is mirrored in Arabic keeps passing if forward arrows keep that attribute and closed menus keep their rows out of the DOM. The check that the first icon inside `#how` is rotated at 1280px refers to a section that no longer exists. Point it at the forward arrow in `#journey` and assert `scale: -1 1`. The accessibility spec runs axe for WCAG 2.2 AA on every golden page in both languages and must report zero violations. The mobile overflow spec already covers `/try-on`. It must pass for the landing, pricing and try-on pages from 320 to 1440 in both languages, with no sideways scroll and no clipped text. Add `/try-on` to the accessibility spec inside that spec itself, not through `e2e/golden-pages.ts`. The overflow spec already lists `/try-on`, and a second entry would create duplicate test titles, which stop Playwright loading the spec. `docs/golden-landing-standard.md` also keeps try-on out of the golden list on purpose. CI runs only `npx playwright test golden-standard- mobile-overflow.spec.ts` against a build with no secrets, so every try-on route answers 503 there. Name the new specs `golden-standard-*.spec.ts` so CI runs them, and stub `/api/try-on/*` with `page.route` wherever a spec needs the try-on API. Add a new end to end spec for the landing story. It should check that a sheet really pins, that one wheel gesture or one arrow key moves exactly one beat, that nav items and hash links land on the right scene, that switching language mid-story keeps the beat and flips `dir` on `<html>` straight away, that covered sheets are inert, and that with reduced motion nothing is pinned. Add a spec for the try-on page in mock mode. It should pick a sample photo and see the stored look, upload a small image and see the mock result, force an out of credits response and see the failure state with its two ways forward, and check that the piece picker and compare dialogs trap and restore focus. Add a spec for pricing. It should check that the currency toggle switches to EGP and back, that the first question is open and only one opens at a time, and that every button has a real destination.

Manual checks. Look at every page at 320, 343, 360, 375, 390, 414, 768, 1024, 1280, 1440 and 1920 wide, in English and Arabic, in light and dark, with motion on and with reduced motion. Compare against `design/screens` at 390 and 1440. Try the landing story with a mouse wheel, a trackpad, the keyboard alone, and touch on a real iPhone in Safari and a real Android phone in Chrome. Watch in particular for the mobile toolbar resizing the viewport, for a fling skipping more than one beat, and for taps being swallowed after a swipe. Open the phone menu and check that Sign in is its first row. Check that the menu traps focus, that Escape closes it and that the page behind doesn't scroll. On desktop check that Sign in is visible in the header beside the language switch, as the updated guard in `AGENTS.md` says. Copy the store password in Chrome, Safari and Firefox, and inside an iframe that blocks the clipboard, and check that the fallback selects the value. Follow every link on every page once and confirm where it lands. There is no staging environment. With `TRYON_MODE=live` and keys from the owner, make a real look from an uploaded photo on `/try-on` on your machine. After deployment the owner checks the demo store's own Generate, as `05-backend.md` describes. Also check the landing at 844 by 390 in landscape, where the story shows as stacked sections. Check the currency toggle with an Egyptian and a non-Egyptian connection or cookie. Run a screen reader pass with VoiceOver or NVDA over the landing story, the try-on flow and the pricing questions.

Speed. On a mid-range phone profile over 4G, the landing's largest contentful paint stays under 2.5 seconds, layout shift under 0.1, and no task blocks the main thread for more than 200ms while moving through the story. The try-on and pricing pages should do at least as well as they do today. Check the JavaScript size of the landing route before and after, and split the heavy story scenes so the first screen doesn't wait for them.

The pull request. Work on a branch such as `feat/site-v15` and open a pull request against `main`, because pushing to `main` deploys to production. Use Conventional Commit messages with a scope. The description should list which parts of this handoff are done, every test changed and why, and the updated `AGENTS.md` sign-in guard and golden standard motion list. It should also list the environment variables the owner must set, the known gaps from `05-backend.md` and anything you couldn't verify, especially if you could only use mocks for something. Attach before and after screenshots for each page at 390 and 1440 in both languages. CI (`next-release-check.yml`) must be green: audit, tests, typecheck, lint, the Docker build and scan, and the golden Playwright specs.

Done means all of this is true. The three pages match the design screenshots in both languages at 390 and 1440 and hold together from 320 to 1920. Every link and button leads somewhere real. The try-on page makes a real look from an upload in live mode. Pricing renders the live catalog in USD and EGP. The demo store's own try-on generates again. The checks above pass, and the owner has reviewed the pull request.
